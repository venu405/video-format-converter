## 三、性能与质量证据

> 以下数字来自 [会话总结.md §当前结论](../会话总结.md) 的固定样本多次运行取中位数，**不提前编造**。

| 指标 | 智能直拷 | H.264 CRF 23 重编码 | 差距 |
|---|---|---|---|
| 速度 | 1× | 1/20.65 | **+20.65 倍** |
| 耗时 | 基线 | 基线 × 20.65 | **-95.16%** |
| SSIM（画面相似度） | **1.0**（逐帧一致） | < 1.0（有损） | 直拷严格优于重编码 |
| PSNR | **∞ dB**（无失真） | 有限值 | 直拷严格优于重编码 |

**结论**：当用户只是更换兼容容器时，不再无意义地重新压缩。代价是没有降低码率来缩小文件——这是 **有意识地不做** 的优化（详见 [会话总结.md §后续可改进](../会话总结.md)）。

## 六、设计目标的"给人用"与"不做不可测的东西"

> 对应面试题第 7 点："项目设计目标给人用，不要做的东西已都明明还甚至都不好测试"（OCR，原意为"不要做明知不好测试的东西"）。

**给人用的具体落点**：

| 面向 | 落地 |
|---|---|
| 普通用户（非开发者） | 队列式而非参数式 UI；预设（MP4/H.264 等）隐藏在"输出格式"按钮后 |
| 视觉简洁 | Apple 设计系统，单一操作色，UI chrome 退后 |
| 窄屏可用 | 1440 + 390 双断点实测无横向溢出 |
| 失败可见 | 单个文件失败不阻断整批，失败项显示 FFmpeg 错误 + "复制命令"按钮（规划中） |
| 透明可控 | 智能直拷与重编码显式区分，界面明确提示"无损直拷"或"已转码为 X" |

**不做不可测的东西的具体例子**（避免无意义优化）：

| 不做 | 原因 |
|---|---|
| 主观"画质提升 N%" | 无固定样本无法验证，营销数字不可信 |
| 持续进度条百分比（基于字节） | 码率波动会让进度条来回跳（详见 [会话总结.md §五个必踩的坑](../会话总结.md)） |
| 解锁音乐平台加密格式 | 法律风险（详见 [分发与合规规范.md](分发与合规规范.md)），公开版已移除 |
| 粉红色旧版主题 | 与本次明确授权的 UI 重设计冲突，保留简洁转换工作台即可 |
