# 视频格式转换技术说明

## 目标

在不接入 FFmpeg 编程接口的前提下，通过本地 FFmpeg 命令行完成视频探测、缩略图生成和格式转换。功能延续原有鼠鼠桌面界面，不上传用户视频到云端。

## 实现

选择单个视频后，前端把文件临时发送到本机服务的 `/api/media-info`。服务端执行 FFmpeg 命令读取媒体流信息，并在视频约 10% 的位置截取一张最长边不超过 480 像素的 JPEG 缩略图。界面显示：

- 时长、分辨率、帧率和总码率；
- 视频编码、音频编码；
- 视频缩略图。

开始转换时仍通过 FFmpeg 命令行执行。新增的“智能转换”先检查目标容器能否直接容纳源视频和音频编码：

- MP4/MOV：视频为 H.264、H.265/HEVC、AV1 或 MPEG-4，且音频兼容时可以直拷；
- MKV：普通非透明视频流可以直拷；
- WebM、带透明通道的视频或编码不兼容的组合会重新编码；
- 用户明确选择 H.264、H.265 或 AV1 时始终重新编码。

直拷使用 `-codec copy`，只改变封装，不重新生成画面和声音。重新编码继续使用项目原有的质量档位：H.264 为 libx264、medium、CRF 23；H.265 为 libx265、medium、CRF 28；AV1 为 libsvtav1、preset 8、CRF 32。带透明通道的视频仍先合成指定背景色，避免透明区域意外变黑。

## 为什么选择这个方案

单纯把所有视频重新编码成 H.264，兼容性高，但即使源编码已经适配目标容器，也会浪费 CPU 时间并产生二次有损压缩。智能直拷把“换容器”和“换编码”分开：兼容时优先速度与原画质，不兼容时才为可播放性付出转码成本。

没有默认使用显卡编码。显卡型号、驱动和编码器支持差异较大，直接启用会降低“下载即可用”的稳定性；当前 CPU 编码可重复、跨机器行为更一致。后续可以把硬件编码做成探测成功后才出现的可选项。

## 实测结果

运行 `npm run benchmark:video` 可以重复生成样本并写出 `output/video-benchmark/results.json`。本次测试环境：Windows 11、Intel Core i7-12650H、Node.js 24.19.0、项目固定 FFmpeg 8.1.1。样本为 8 秒、1280×720、30 FPS、H.264 + AAC 的 MP4，输出 MKV。

| 方案 | 重复次数 | 中位耗时 | 输出大小 | SSIM | PSNR |
|---|---:|---:|---:|---:|---:|
| 智能无损直拷 | 5 | 92 ms | 4,965,819 字节 | 1.000000 | ∞ |
| H.264 CRF 23 重编码 | 3 | 1,900 ms | 3,129,187 字节 | 0.995670 | 44.452305 dB |

在这个固定样本和机器上，智能直拷是重编码的 **20.65 倍速度**，转换耗时减少 **95.16%**，并且没有二次压缩造成的画面损失。它的取舍是输出比本次 CRF 23 重编码结果大 **58.69%**；因此不能笼统宣称“文件更小”，准确说法是“兼容场景明显更快且保持原画质”。不同视频长度、磁盘、处理器和源文件码率会改变具体数字。

质量比较前会按帧序号重建时间轴。原因是换封装可能调整首帧时间戳，如果直接按时间戳比较，会把不同帧错配并得到虚假的质量损失。

## 验证

- 核心解析、静态界面和真实 FFmpeg 集成测试：37 项通过；
- 原项目视频相关集成测试：7 项通过；
- Electron 安全与桌面边界测试：27 项通过；
- `/api/media-info` 真实样本：正确返回 8 秒、1280×720、30 FPS、H.264、AAC 和 JPEG 缩略图；
- `/api/convert` 真实样本：返回 `stream-copy`，端到端耗时 94 ms；
- Playwright 页面验收：信息面板、缩略图、智能选项和无损直拷结果均可见，控制台错误和页面错误均为 0。
- Electron 43.1.0 桌面启动冒烟通过，窗口成功启动本地服务。

完整测试套件还依赖源码仓库未附带的 LibreOffice、Poppler、Tesseract 等大型引擎。本次只恢复并校验了项目发布清单中的 FFmpeg，所以与文档、PDF、OCR 有关的测试未作为视频改动的验收结果。

## 已知边界

- 直拷不会降低码率，文件大小主要取决于源视频；
- WebM 有严格的编码组合限制，因此当前始终使用 VP9 + Opus 转码；
- 只有单视频选择时显示详细信息和缩略图，批量模式保留原有列表体验；
- FFmpeg 缩略图失败不会阻止转换，界面仍会显示已读取到的媒体信息；
- 当前长任务显示不确定进度动画，尚未解析 FFmpeg 的逐帧实时进度。
